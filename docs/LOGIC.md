# Scope3 AI 파이프라인 동작 로직

`scope3_pipeline_claude.py`(Claude 버전)를 기준으로 정리한 문서입니다. OpenAI 버전은 LLM 호출부만 다르고 계산 로직은 같습니다.
사용법은 [README.md](../README.md)를 보세요. 이 문서는 "내부에서 무슨 일이 일어나는가"를 다룹니다.

---

## 1. 전체 흐름

```
입력 템플릿(xlsx)
   │
   ▼
run_scope3_pipeline()                    ← 진입점 (CLI/Colab 공통)
   │
   ▼
process_template_inventory()             ← 시트명이 C1, C2…로 시작하면 "새 템플릿"으로 판단
   │
   ▼
process_new_template()                   ← 시트별 루프
   │   ① read_template_sheet()           헤더 행 탐지 + 시트 읽기
   │   ② standardize_cX_sheet()          컬럼명 통일, 월별→합산
   │   ③ 회사별 매핑 폴백                C5/C6/C7의 빈 칸 채움
   │   ④ 카테고리별 계산                 EF 매칭 + 단위 환산 + 배출량 계산
   │
   ▼
카테고리별로 합쳐 *_result.xlsx 저장       ← 진단용 상세 결과
   │
   ▼
_postprocess_scope3_result_file()        ← C1/C2 단위, C6/C7 산식, C11/C14 재검증
   │
   ▼
build_filled_template()                  ← 원본 템플릿의 회색 칸(배출계수·배출량)에 값 채움
   │
   ▼
*_filled_template.xlsx 저장
```

결과물은 항상 2개입니다.

| 파일 | 용도 |
|---|---|
| `<입력명>_result.xlsx` | 진단용. 카테고리별 EF 매칭명, 단위 환산 비고, 추천 후보 등 중간값 전부 포함 |
| `<입력명>_filled_template.xlsx` | 제출용. 원본 템플릿 형식 그대로, 배출계수·배출량 칸만 채워짐 |

## 2. 입력 처리 (공통)

### 2.1 시트 라우팅
`SHEET_PROCESSOR_MAP`이 **시트명 → (표준화 함수, 카테고리)** 를 정합니다. 시트명이 바뀌면 처리되지 않으니 템플릿 시트명은 바꾸지 마세요.
매핑에 없는 시트(`기업정보`, `배출계수_드롭다운`, `회사별_*` 등)는 `[skip]` 됩니다.

| 시트 | 카테고리 | 산정 방식 |
|---|---|---|
| C1_구매품서비스 / C2_자본재 | 1 / 2 | 지출 기반 |
| C3_연료에너지 | 3 | 활동량 기반 |
| C4-1 / C9-1 운송거리 | 4 / 9 | 거리 기반 |
| C4-2 / C9-2 운송금액 | 4 / 9 | 지출 기반 |
| C5_사업장폐기물 | 5 | 활동량 기반 |
| C6-1 출장거리 / C6-2 출장비 | 6 | 거리 / 지출 기반 |
| C7_임직원통근 | 7 | 거리 기반 |
| C8-1·2·3 / C13-1·2·3 | 8 / 13 | 에너지(직접·면적배분·인원배분) |
| C11_판매제품사용 | 11 | 활동량 기반 |
| C12_판매제품폐기 | 12 | 활동량 기반 |
| C14_프랜차이즈 | 14 | 활동량 기반 |
| C15_투자 | 15 | 지분율 기반 |

C10(판매제품 가공)은 템플릿에 없습니다.

### 2.2 헤더 탐지와 컬럼 정규화
- 템플릿은 헤더가 2단(예: `월별 사용량` 아래 `1월~12월`)이라 `detect_template_header_row()`가 헤더 행을 자동으로 찾습니다.
- 필수 표시 `*`는 제거하고 컬럼명을 통일합니다(`*국가` → `국가`).
- 드롭다운용 보조 목록이 데이터로 읽히지 않도록 빈 행을 걸러냅니다.

### 2.3 월별 / 연간 입력
한 행에 월별(1월~12월)과 연간 칸이 같이 있습니다. 월별 값이 있으면 **월별 합산**을 쓰고, 없으면 연간 값을 그대로 씁니다.
(`_sum_monthly`, `_patch_collapse_monthly_to_value`) 이후 계산은 합산된 값 하나로 진행됩니다.

### 2.4 회사별 자동매칭 폴백
엑셀 수식(`상세 폐기물명 → 폐기물 종류`, `상세 교통수단명 → 교통수단`)이 재계산되지 않은 채 업로드되면 해당 칸이 비어 있습니다.
이때 `_fill_missing_from_company_mapping()`이 `기업정보!C7`의 회사명으로 `회사별_폐기물매핑` / `회사별_교통수단매핑` 시트를 직접 읽어 빈 칸을 채웁니다.
이미 값이 있는 칸은 건드리지 않습니다.

`data/배출계수_통합_DB.xlsx`를 시작 시 한 번 읽습니다(`_load_ef_sheet`).

| DB 시트 | 쓰이는 곳 |
|---|---|
| 구매_USEPA | C1, C2 (지출 기반, KRW 환산 EF 컬럼) |
| 에너지 | C8, C11, C13, C14 |
| 에너지_C3 | C3 (업스트림·송배전 손실분만 반영한 별도 EF) |
| 운송 | C4-1, C9-1 (ton-km 기준) |
| 운송_Spend | C4-2, C9-2 |
| 출장_통근 | C6-1, C7 |
| 출장_Spend | C6-2 |
| 폐기물_C5 | C5 |
| 폐기물_C12 | C12 (코드 계층: 대·중·소분류) |

보고연도(`--report-year`, 기본 2025)에 맞는 **기계산 KRW EF 컬럼**(kgCO2e/원)을 골라 지출 기반 산정에 직접 씁니다.
해당 컬럼이 DB에 없을 때만 USD EF × 한국은행 월평균 환율로 폴백합니다.

## 4. 카테고리별 계산식

모든 배출량은 **tCO2e**로 출력합니다. EF 단위가 kg 기준이라 마지막에 `/1000`이 붙습니다.

| 카테고리 | 계산식 | EF 선택 방식 |
|---|---|---|
| C1, C2 | 지출금액(원) × EF(kgCO2e/원) / 1000 | 품목명·품목군으로 구매_USEPA 후보 랭킹 후 1순위 사용 |
| C3 | 사용량 × EF / 1000 | 에너지_C3에서 에너지명 매칭, 단위 환산 |
| C4-1, C9-1 | 거리(km) × 중량(ton) × EF(kgCO2e/ton-km) / 1000 | 운송수단을 코드(road/rail/sea/air 등)로 정규화 후 조회 |
| C4-2, C9-2 | 운송금액 × EF / 1000 | 운송_Spend에서 운송항목 매칭 |
| C5 | 처리량(kg) × EF(kgCO2e/kg) / 1000 | 폐기물종류 × 처리방법(매립/소각/재활용) |
| C6-1 | 편도거리 × 2 × 인원수 × 이동횟수 × EF / 1000 | 교통수단을 표준코드로 정규화 후 출장_통근 조회 |
| C6-2 | 출장비 × EF / 1000 | 출장_Spend에서 출장항목 매칭 |
| C7 | 인원수 × 편도거리 × 2 × 근무일수 × EF / 1000 | C6-1과 동일. 근무일수 미입력 시 245일 |
| C8, C13 | 사용량 × EF / 1000 | 에너지 시트에서 에너지명 매칭 |
| C8/C13 면적 | 건물전체 사용량 × (사용면적 / 건물전체면적) 후 위와 동일 | |
| C8/C13 인원 | 건물전체 사용량 × (자사인원 / 건물전체인원) 후 위와 동일 | |
| C11 | 제품수량 × 제품당 연간 사용량 × (수명개월/12) × EF / 1000 | 에너지 시트 |
| C12 | 판매량 × 제품중량 × Σ(처리비중 × 처리방법별 EF) / 1000 | 소분류 > 중분류 > 대분류 코드 순으로 매칭 |
| C14 | 사용량 × EF / 1000 | 에너지 시트 |
| C15 | (피투자기업 Scope1 + Scope2) × 지분율(%) / 100 | EF 없음 |

### 세부 규칙
- **왕복 처리 (C6-1, C7)**: 입력은 편도 거리이므로 기본으로 ×2 합니다. `비고`·`설명/적요`·`단위환산비고` 컬럼에 "왕복" 또는 "round trip"이 있으면 이미 왕복 거리로 보고 ×1 합니다.
- **통근 거리 검증 (C7)**: 지오코딩 결과가 편도 100km를 넘으면 동명이지 오매칭 가능성이 커서 LLM이 직선거리를 다시 추정하고 그 값으로 교체합니다.
- **C12 처리비중**: 매립·소각·재활용 비중이 모두 비어 있으면 세 방식의 전체 평균 EF를 씁니다. 코드·제품명 매칭이 모두 실패해도 전체 평균 EF(`WASTE_AVG_EF`)로 대체합니다.
- **C12 소분류 코드 형식**: `01-01-02 | 폐폴리프로필렌`처럼 코드와 이름이 합쳐진 문자열에서 `|` 앞부분만 코드로 씁니다.
- **C3 vs C8/C13**: C3는 직접연소·Scope2가 아니라 업스트림과 송배전 손실분만 해당하므로 `에너지_C3` 시트의 별도 EF를 씁니다. 같은 에너지라도 EF가 다릅니다.

## 5. 단위 환산

`convert_energy_unit`, `convert_to_base_unit`이 입력 단위를 EF 기준 단위로 맞춥니다.

- 중량: g, kg, ton, lb 등 → kg 또는 ton
- 에너지: kWh, MJ, GJ 등 서로 변환하고, 연료는 L·kg·Nm³ 같은 EF 기준 단위로 맞춤 (`ENERGY_BASE_UNIT`, `ENERGY_NAME_ALIAS` 참고)
- 화폐: 원이 아닌 통화는 한국은행 USD/KRW 월평균 환율로 환산 (`get_bok_usd_krw_monthly_avg`)
- 환산 결과는 `단위환산비고` 컬럼에 남습니다. 표에 없는 단위는 LLM에게 환산계수를 물어보고, 이때는 비고에 "AI 판단"이 붙습니다.
- 도시가스(LNG)처럼 DB에서 항목이 바뀐 경우, 두 연료의 발열량(LHV)을 거쳐 단위를 이어 줍니다(`_bridge_convert_via_lhv`).

## 6. LLM(Claude)이 쓰이는 곳

모델은 코드에 `claude-sonnet-5`로 지정돼 있습니다. LLM은 **사람이 입력하기 어려운 매핑·추정**에만 쓰고, 최종 계산식과 EF 값은 항상 DB와 코드가 정합니다.

| 용도 | 함수 | 호출 조건 |
|---|---|---|
| 운송수단 추정 | `_ai_infer_transport_mode` | 키워드 규칙으로 판별 실패 시 |
| 교통수단 정규화 | `_ai_normalize_travel_mode` | 규칙 매핑 실패 시 |
| 출발지·도착지 직선거리 추정 | `_ai_estimate_straight_km` | 지오코딩 실패 시 |
| 가까운 공항 찾기 | `_ai_nearest_airport` | 항공 구간인데 출발지·도착지가 공항이 아닐 때 |
| 구매 품목 번역·분류 | `translate_product_for_search`, `_infer_group_name_llm` | 구매_USEPA 후보 검색 보조 |
| 단위 환산계수 추정 | `_ai_unit_conversion_factor` | 환산표에 없는 단위 |

텍스트·JSON 호출 함수(`_call_claude_text`, `_call_claude_json`)는 실패 시 기본 3회 재시도합니다. 일부 함수는 `lru_cache`로 같은 입력의 재호출을 막습니다.
`ANTHROPIC_API_KEY` 환경변수가 없으면 시작 시점에 에러로 중단됩니다(키는 필수).

### 거리 계산 (`get_distance_km`)
1. 항공이면 출발지·도착지를 가까운 공항으로 치환
2. 지오코딩으로 **직선거리** 계산, 실패하면 LLM이 직선거리 추정
3. 직선거리 × **수단별 보정계수**로 실이동거리 산출 (도로 1.3, 택배 1.35, 항공 1.09, 해상 1.30, 철도 1.20)
4. `validate_distance_km`으로 수단별 상식 범위 검증
5. 위 과정이 모두 실패한 경우에만 LLM이 실이동거리를 직접 추정

입력된 `운송거리(km)` / `편도거리(km)`가 있으면 추정 없이 검증만 하고 그대로 씁니다.

## 7. 생물기원 CO2 분리 (C5, C12)

음식물류·폐지류·폐목재류를 **소각**한 배출은 생물기원 CO2가 섞여 있어 화석기원분만 Scope 3에 집계합니다.

```
배출량(tCO2e) = 화석기원 CO2e(tCO2e)   ← 집계에 쓰이는 값
생물기원 CO2e(tCO2e)                    ← 별도 컬럼에 참고용으로만 기록
```

화석탄소비율(`BIOGENIC_WASTE_FCF`): 음식물류 0.0 / 폐지류 0.01 / 폐목재류 0.0 (출처: IPCC 2006 Vol.5 Table 2.4).
소각이 아닌 처리방법은 분리하지 않습니다. C12는 처리비중이 하나도 없으면 소각분을 알 수 없어 분리하지 않습니다.

## 8. 결과 파일 작성

1. `_result.xlsx`: 카테고리별로 시트를 합칩니다(C4-1과 C4-2는 `C4_업스트림운송` 한 시트). 환율·NAICS 등 내부 중간 컬럼과 빈 컬럼은 제거합니다.
2. `_postprocess_scope3_result_file`: 저장된 결과를 다시 읽어 C1/C2 단위, C6/C7 산식, C11/C14 에너지 계산을 재검증하고 보정합니다.
3. `build_filled_template`: 원본 템플릿을 열어 **회색 칸(배출계수·배출량)** 위치를 찾아 결과 값을 같은 순서로 채웁니다. 한 카테고리 결과 시트에 여러 원본 시트가 이어 붙어 있으므로 커서를 두고 순서대로 잘라 대응시킵니다.
   - 배출계수 칸에 `AI 추천`, 배출량 칸에 `AI 자동산정` 같은 안내 문구가 있던 행도 이 단계에서 숫자로 바뀝니다.

## 9. 코드를 읽을 때 알아둘 점

- **파일이 9,000줄 이상이고 같은 이름의 함수가 여러 번 정의돼 있습니다.** 원본 Colab 노트북의 셀을 순서대로 이어 붙인 구조라, 뒤쪽 셀의 `PATCH` 정의가 앞쪽 정의를 덮어씁니다. 어떤 함수가 실제로 쓰이는지 보려면 **파일에서 가장 마지막에 정의된 것**을 보세요.
  (예: `calc_transport`는 1214행과 6511행, `lookup_energy_ef`는 425행·6705행·7387행·8100행에 있고 실제로는 마지막 것이 동작합니다.)
- `# ── [원본 셀 N] ─` 주석이 Colab 노트북 셀 번호와 1:1 대응합니다. `.py`를 고치면 노트북의 같은 번호 셀도 같이 고쳐야 합니다.
- 계산 로직을 고칠 때는 Claude 버전과 OpenAI 버전 두 파일을 함께 수정해야 합니다.
- 템플릿 컬럼명을 바꾸면 `KNOWN_TEMPLATE_HEADERS`(헤더 탐지)와 해당 `standardize_cX_sheet`의 컬럼 참조를 같이 확인해야 합니다.
